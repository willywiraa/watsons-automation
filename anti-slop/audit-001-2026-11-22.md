# antislop audit 001 (2026-11-22)

What was checked: the app page (`launcher/ui.html`), which the desktop launcher and the hosted server both use, plus the code comments in `launcher/`, `server/`, `src/` and `tests/`. The portfolio prototype and the other HTML files were not checked.

How: the code was read, and the app was run with a fake project (it never opens the Watsons site) at 390, 900 and 1280 px in Edge. Colour contrast was computed with the WCAG formula, in light and dark.

Priority comes from the rule's tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW. Nothing has been changed. Pick the numbers you want fixed.

## HIGH

**1. R-03: the page scrolls sideways below 1024 px.**
`body{min-width:1024px}` (ui.html:284). At 900 px, the narrowest width the design doc supports (UI-UX-PRD.md:80), the page is 124 px wider than the window. On a phone (390 px) everything is laid out at 1024 px. The design doc lists a phone layout as a non-goal, so there are two ways to fix it: lower the minimum to 900 px to match the doc (small change), or build a real phone layout (large change).

**2. R-27: Logs / History has no error state.**
If loading the history fails, `loadHistory` stops without a message (ui.html:2527-2528). On the first load the page stays on "Loading…", and Refresh shows nothing. It should say that the history could not be loaded and offer Try again.

**3. R-25: some small text is below 4.5:1 contrast.**
- The **Running** status pill in light mode: 4.47:1.
- The numbered circles in a run's Execution activity (12 px): 4.10 to 4.49:1 in light mode, and 4.43:1 for the grey one in dark mode.
- The line numbers beside the products box in light mode: 4.39:1.

Everything else passes, for example secondary text at 7.6:1 and the other pills at 4.6 to 5.1:1. The fix is a slightly darker text colour or a lighter tint for these three cases.

**4. R-39: the Automation page has no main heading.**
The sidebar title "Automation" is a plain `div` (ui.html:641), so screen readers find no `h1` and the headings start at `h2`. Logs / History and Sign in do have an `h1`. The fix is to make that title an `h1`, with no visual change.

**5. R-02: em dashes are used as "no value" markers.**
There are 10 in ui.html (lines 1092, 2179, 2415, 2644, 2648, 2670, 2671, 2675, 2681 and 2742), for example in the Delivery, Error and Operator cells and in Order results. Screen readers read them aloud as "em dash". Replace them with a muted word such as "None", or with an empty cell. README, docs and server messages have none.

**6. R-02: three pieces of text read awkwardly.**
- "All 1 shown" under the history table (ui.html:2584). Better: "1 run shown" / "All 12 runs shown".
- "Start using app" on the walkthrough's button (ui.html:985). Better: "Start using the app".
- "Something went wrong" as the heading of a run's error question (ui.html:1579). It names no problem. The heading should say what failed.

## MEDIUM

**7. R-04: no written reason for the icon set.**
The icons are Lucide, "as in the design prototype" (ui.html:1000). All 26 are functional (bag, check, copy, image, and so on), with no sparkles or other decorative icons. But design doc section 9.4 never says why this set was chosen. The fix is one line in the design doc, with no visual change.

## LOW

**8. R-31: an open history row repeats Copy and Approve.**
When a row is open, **Approve** appears twice: in the row and in Order results. Copy also appears twice: the row's hover Copy and the Copy in Order results. The hover Copy also covers the start of the Delivery column. Suggestion: hide the row's Copy and Approve while its details are open, and keep them on closed rows.

**9. R-31: the run result card has two copy buttons for the same number.**
There is a "Copy" beside the order number and a "Copy order number" button among the actions below it. Keep one.

**10. R-31: an open row says "awaiting approval" five times.**
It appears in the Status column, in the Error column (as "Needs approval", in warning colour, though it is not an error), in the summary sentence, on the Order results pill, and in Execution activity. Design doc G3 says each view states the state once. Suggestion: show no error in the Error column for this status.

**11. R-05: the Operator column cuts off short names.**
At 1280 px, "Test Operator" shows as "Test Ope…". The full name is only in a mouse-hover tooltip.

**12. R-31: step names mix capital styles.**
"Product Search" and "Pickup Store Selection" use Title Case, while "Add to bag", "Cart validation" and "Approve order" use sentence case. Changing them touches the order flows, the tests and how old runs read. That is low value and medium risk, so this one is optional.

**13. antislop-code (R-31): code comments carry history and decoration.**
- 33 banner comments made of dash runs, for example `// ---- Form ------…`. There are 27 in ui.html, 6 in launcher.cjs and some in tests.
- About 430 comment lines carry a change date or "user's request", for example "(user's request 2026-10-30)". Git already keeps that history.
- 15 comment blocks in ui.html and 31 in launcher.cjs run three lines or more.

Only comments would change, never the code, and the full test suite would run afterwards. This is the largest item by line count, so it can be done one folder at a time.

## Checked and fine

- **Focus:** a visible focus ring on every control (`:focus-visible`), and each removed outline has a replacement.
- **Targets:** no control below WCAG's 24 px minimum target at desktop width.
- **Pointer:** a pointer cursor on every control.
- **Dialogs:** they close with Escape.
- **Page structure:** `lang`, `title`, header, nav and main are present.
- **Dark mode:** it passes everywhere except the one grey circle in item 3.
- **Text:** no buzzwords or emoji.
- **Visual effects:** no gradients, glows or blur. Shadows only on dialogs.
- **Left stripes:** the coloured left stripes mark a real state (a run's question, the chosen option).
- **Empty and loading states:** these exist for history and runs.
